1. Perceivable

Information must be perceivable; not by colour alone, not silently, not at unreadable sizes.

color-contrast

#

Elements must meet minimum color contrast ratio thresholds

Text does not meet the minimum contrast ratio against its background (4.5:1 for normal text, 3:1 for large text), making it difficult to read.

How to fix

  • Darken the text or lighten the background until the ratio passes.
  • Check background images and gradients behind the text, not only the flat colour.
  • Do not rely on colour alone to convey meaning; pair it with an icon or label.
WCAG 1.4.3AA Full reference (dequeuniversity.com) ↗ ← Back to scanner

image-alt

#

Images must have alternative text

An <img> element has no alt text (or an empty value where one is required), so screen readers cannot describe it.

How to fix

  • Add alt="..." describing the purpose of the image, not merely its appearance.
  • For purely decorative images, use alt="" so that screen readers skip them.
  • For images that function as links or buttons, the alt text becomes the accessible name of that control.
WCAG 1.1.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

input-image-alt

#

Image buttons must have alternative text

An <input type="image"> button has no alt text, so its purpose is invisible to assistive technology.

How to fix

  • Add alt="..." describing the action, for example alt="Search".
  • Alternatively, use a regular <button> element containing text.
WCAG 1.1.1 / 4.1.2A Full reference (dequeuniversity.com) ↗ ← Back to scanner

svg-img-alt

#

<svg> elements with an img or image role must have alternative text

An SVG used as an image has no accessible name; screen readers may announce it as "graphic" or skip it entirely.

How to fix

  • Add role="img" together with aria-label, or a <title> element inside the SVG.
  • For decorative SVGs, add aria-hidden="true" and focusable="false".
WCAG 1.1.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

role-img-alt

#

[role="img"] and [role="image"] elements must have alternative text

An element marked role="img" has no accessible name describing the image it represents.

How to fix

  • Add aria-label or aria-labelledby with a description.
  • If the element is decorative, use role="presentation" or aria-hidden instead.
WCAG 1.1.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

object-alt

#

<object> elements must have alternative text

An <object> embed (a PDF or similar content) provides no fallback text if the content cannot load.

How to fix

  • Provide fallback content inside the <object> tags.
  • Prefer modern embed methods, or link to the file directly.
WCAG 1.1.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

video-caption

#

<video> elements must have captions

A <video> element has no captions track, so deaf and hard-of-hearing users cannot follow the audio content.

How to fix

  • Add a <track kind="captions"> element referencing a .vtt file.
  • For background video, mute it or provide a transcript nearby.
WCAG 1.2.2A Full reference (dequeuniversity.com) ↗ ← Back to scanner

audio-caption

#

<audio> elements must have a captions track

An <audio> element has no captions, so its spoken content is unavailable to deaf users.

How to fix

  • Add a captions track, or provide a link to a transcript.
  • If the audio is ambient or background, determine whether captions are required at all.
WCAG 1.2.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

no-autoplay-audio

#

<video> or <audio> elements must not play automatically

Media plays automatically for more than three seconds without a mechanism to pause or control it, which is disruptive for screen reader and low-vision users.

How to fix

  • Remove autoplay, or provide controls and pause playback after three seconds.
  • Never autoplay media with sound.
WCAG 1.4.2A Full reference (dequeuniversity.com) ↗ ← Back to scanner

link-in-text-block

#

Links must be distinguishable without relying on color

Links within paragraphs are distinguished only by colour; users who cannot perceive that difference cannot identify them as links.

How to fix

  • Add an underline (default link styling already provides one).
  • Or use a non-colour cue such as bold text or an icon.
WCAG 1.4.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

meta-viewport

#

Zooming and scaling must not be disabled

The viewport meta tag sets user-scalable=no or maximum-scale=1, preventing users from zooming the page.

How to fix

  • Remove user-scalable=no and maximum-scale restrictions.
  • A plain content="width=device-width, initial-scale=1" is sufficient.
WCAG 1.4.4AA Full reference (dequeuniversity.com) ↗ ← Back to scanner

avoid-inline-spacing

#

Inline text spacing must be adjustable with custom stylesheets

Text containers clip content when users apply their own letter, word, or line spacing overrides; this particularly affects users with dyslexia and low vision.

How to fix

  • Remove fixed heights on text containers so content can grow.
  • Avoid !important on line-height and letter-spacing rules.
WCAG 1.4.12AA Full reference (dequeuniversity.com) ↗ ← Back to scanner

table-fake-caption

#

Data or header cells must not be used to give caption to a data table

A table caption is simulated with a cell rather than a real <caption> element, so assistive technology does not announce the table’s purpose.

How to fix

  • Use <caption> as the first child of <table>.
  • Or use aria-label / aria-labelledby on the table.

th-has-data-cells

#

Table headers in a data table must refer to data cells

A header cell (<th>) is not associated with any data cells; screen reader users hear a heading with no content beneath it.

How to fix

  • Ensure each <th> governs at least one data cell through correct row and column structure.
  • If the cell is decorative, use <td> or aria-hidden instead.

autocomplete-valid

#

autocomplete attribute must be used correctly

A form field uses an autocomplete token that does not match the field’s purpose (for example, autocomplete="email" on a phone number field).

How to fix

  • Use the correct token from the HTML specification (name, email, tel, street-address, and so on).
  • Set autocomplete="off" explicitly if the field should genuinely not autofill.

aria-meter-name

#

ARIA meter nodes must have an accessible name

A meter widget (role="meter") has no accessible name, so screen readers announce a value without indicating what is being measured.

How to fix

  • Add aria-label or aria-labelledby describing what the meter measures.
  • Or use the native <meter> or <progress> element where its semantics apply.

aria-progressbar-name

#

ARIA progressbar nodes must have an accessible name

A progressbar widget has no accessible name, so screen readers announce a percentage without context.

How to fix

  • Add aria-label or aria-labelledby (for example, "Upload progress").
  • Or use the native <progress> element.

css-orientation-lock

#

CSS must not lock display orientation

CSS forces the page into portrait or landscape only, so users whose device is oriented differently cannot use it.

How to fix

  • Remove orientation-locking CSS and allow the layout to reflow in both orientations.

p-as-heading

#

Styled <p> elements must not be used as headings

A <p> element styled to look like a heading (large and bold) is not a real heading, so screen reader heading navigation skips it.

How to fix

  • Replace it with an <h1>–<h6> element and move the styling into CSS.
WCAG 1.3.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

td-has-header

#

Non-empty <td> elements in larger <table> must have an associated table header

A data cell in a multi-row or multi-column table has no associated header, so screen readers cannot announce what the value represents.

How to fix

  • Use <th scope="col"> or <th scope="row"> for headers, or headers="..." referencing the appropriate <th>.
  • For simple data tables, correct <th> markup is usually sufficient.
WCAG 1.3.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

td-headers-attr

#

Table cell headers attributes must refer to other <th> elements in the same table

A headers="..." attribute points to an id that does not exist, is not a <th>, or belongs to a different table.

How to fix

  • Ensure every id in headers= matches a real <th id="..."> in the same table.
  • Keep ids unique across the page.
WCAG 1.3.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

list

#

<ul> and <ol> must only directly contain <li>, <script> or <template> elements

A list contains non-<li> children (divs, spans, or other elements), breaking the list structure that screen readers rely on.

How to fix

  • Make every direct child an <li>; if wrappers are needed, place them inside the <li>.
  • If the content is not genuinely a list, do not use <ul> or <ol>.
WCAG 1.3.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

listitem

#

<li> elements must be contained in a <ul> or <ol>

An <li> element sits outside any list, so it is announced as a stray list item.

How to fix

  • Wrap it in <ul> or <ol>, or change it to a <div> or <p>.
WCAG 1.3.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

definition-list

#

<dl> elements must only directly contain properly-ordered <dt> and <dd> groups

A definition list has broken structure: <dd> without <dt>, incorrect ordering, or stray elements.

How to fix

  • Each <dt> should be followed by its <dd> element(s); only <div> wrappers are permitted between groups.
WCAG 1.3.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

dlitem

#

<dt> and <dd> elements must be contained by a <dl>

A <dt> or <dd> element is used outside a <dl> definition list.

How to fix

  • Wrap them in a <dl>, or use regular headings and paragraphs.
WCAG 1.3.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

aria-required-children

#

Certain ARIA roles must contain particular children

A parent role such as menu, listbox, or tablist is missing the child roles it requires (menuitem, option, tab), so the widget structure is broken.

How to fix

  • Add the required child roles, or use native <ul> or <table> markup that implies the structure.
WCAG 1.3.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

aria-required-parent

#

Certain ARIA roles must be contained by particular parents

An element has a role that requires a specific parent (for example, role="menuitem" outside role="menu"), breaking the announced structure.

How to fix

  • Wrap it in the required parent role, or use native list or table markup.
WCAG 1.3.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

aria-hidden-body

#

aria-hidden="true" must not be present on the document body

aria-hidden="true" on <body> hides the entire page from screen readers; this is usually a leftover from a modal or dialog script.

How to fix

  • Remove it, or scope aria-hidden to the specific overlay element only.
  • Ensure it is removed when the modal closes.

2. Operable

Interfaces must be operable; keyboard reachable, no traps, no seizure risks.

area-alt

#

Active <area> elements must have alternative text

An <area> inside an image map is a clickable link with no alt text, so its destination is invisible to screen readers.

How to fix

  • Add alt="..." describing where the area links to.
  • Remove <area> elements that are not in use.
WCAG 2.4.4 / 4.1.2A Full reference (dequeuniversity.com) ↗ ← Back to scanner

bypass

#

Page must have means to bypass repeated blocks

Keyboard users must tab through the entire navigation and header on every page before reaching the content; no skip link or landmark shortcut is provided.

How to fix

  • Add a "Skip to main content" link as the first focusable element.
  • Or ensure a <main> landmark exists and is reachable.
WCAG 2.4.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

document-title

#

Documents must have <title> element to aid in navigation

The page has no <title> element (or an empty one), so browser tabs, bookmarks, and screen reader page lists display nothing useful.

How to fix

  • Add a unique, descriptive <title> to every page.
  • Lead with the page topic and keep it under approximately 60 characters.
WCAG 2.4.2A Full reference (dequeuniversity.com) ↗ ← Back to scanner

link-name

#

Links must have discernible text

A link has no accessible name: icon-only links, empty anchors, or links whose only content is an unlabelled image.

How to fix

  • Add visible text, aria-label, or aria-labelledby.
  • For icon links, give the SVG or icon an accessible name.
WCAG 2.4.4 / 4.1.2A Full reference (dequeuniversity.com) ↗ ← Back to scanner

marquee

#

<marquee> elements are deprecated and must not be used

Scrolling <marquee> text cannot be paused and presents a distraction and seizure risk; modern browsers also handle it inconsistently.

How to fix

  • Remove it; use static text or a proper animation with a pause control.
  • CSS animation alone is insufficient; WCAG 2.2.2 still requires a stop mechanism.
WCAG 2.2.2A Full reference (dequeuniversity.com) ↗ ← Back to scanner

blink

#

<blink> elements are deprecated and must not be used

Blinking <blink> text is a seizure hazard and is not supported by modern browsers in any case.

How to fix

  • Remove it entirely; never reimplement flashing text with CSS or JavaScript.
WCAG 2.2.2A Full reference (dequeuniversity.com) ↗ ← Back to scanner

meta-refresh

#

Delayed refresh under 20 hours must not be used

A <meta http-equiv="refresh"> tag reloads the page automatically, abruptly removing users (including screen reader users mid-sentence) from the content.

How to fix

  • Remove the meta refresh; use a real link or JavaScript with user control.
  • Session timeouts require a warning and an option to extend the session instead.
WCAG 2.2.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

meta-refresh-no-exceptions

#

Delayed refresh must not be used

The stricter AAA-level variant: no timed refresh is permitted at all, even with user control.

How to fix

  • Remove timed refreshes entirely.
WCAG 2.2.4 / 3.2.5AAA Full reference (dequeuniversity.com) ↗ ← Back to scanner

scrollable-region-focusable

#

Scrollable region must have keyboard access

A scrollable <div> (overflow:auto or scroll) cannot be reached or scrolled using a keyboard alone.

How to fix

  • Add tabindex="0" to the scrollable region.
  • Or preferably, use a natively scrollable element with real content.
WCAG 2.1.1 / 2.1.3A Full reference (dequeuniversity.com) ↗ ← Back to scanner

target-size

#

All touch targets must be 24px large, or leave sufficient space

Buttons and links are too small or too close together to be tapped reliably; the WCAG 2.2 minimum target size is 24×24 CSS pixels, subject to spacing exceptions.

How to fix

  • Increase padding or size to at least 24px in each dimension.
  • Or ensure sufficient spacing between adjacent targets.
WCAG 2.5.8AA Full reference (dequeuniversity.com) ↗ ← Back to scanner

identical-links-same-purpose

#

Links with the same name must have a similar purpose

Two links share the same text (for example, "read more") but lead to different destinations; screen reader link lists become meaningless.

How to fix

  • Make link text unique and descriptive (for example, "Read more about pricing").
  • Or add context via aria-describedby if the visible text must remain short.
WCAG 2.4.9AAA Full reference (dequeuniversity.com) ↗ ← Back to scanner

frame-focusable-content

#

Frames with focusable content must not have tabindex=-1

An <iframe> contains focusable content but has tabindex="-1", which can trap or break keyboard focus within the frame.

How to fix

  • Remove tabindex="-1" from frames that contain interactive content.
  • Ensure keyboard focus can move into and out of the frame.
WCAG 2.1.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

label-content-name-mismatch

#

Elements must have their visible text as part of their accessible name

The visible text of a control is not part of its accessible name (for example, aria-label overrides the button text), so voice-control users who speak the visible label cannot activate it.

How to fix

  • Make the accessible name begin with the visible text, or match it exactly.
  • Do not allow aria-label to contradict the text shown on screen.
WCAG 2.5.3A Full reference (dequeuniversity.com) ↗ ← Back to scanner

server-side-image-map

#

Server-side image maps must not be used

An old-style server-side image map (<img ismap>) produces click coordinates rather than focusable links; keyboard and screen reader users cannot operate it.

How to fix

  • Replace it with a client-side image map of real <a> links, or a plain list of links.

3. Understandable

Interfaces must be understandable; clear labels, declared language, consistent structure.

valid-lang

#

lang attribute must have a valid value

A lang attribute (on html or on a part of the page) uses a value that BCP47 or the specification does not recognise.

How to fix

  • Use a valid language tag such as "en", "en-US", or "fr".
  • Check for typos; an incorrect value silently breaks pronunciation and translation tools.
WCAG 3.1.2AA Full reference (dequeuniversity.com) ↗ ← Back to scanner

html-has-lang

#

<html> element must have a lang attribute

The <html> tag has no lang attribute, so screen readers cannot determine the language and correct pronunciation.

How to fix

  • Add lang="en" (or the correct BCP47 tag) to <html>.
WCAG 3.1.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

html-lang-valid

#

<html> element must have a valid value for the lang attribute

The lang attribute is present but its value is not a recognised language tag.

How to fix

  • Use a valid tag: "en", "en-US", "pt-BR", and so on.
  • Check for typos such as lang="eng" or lang="english".
WCAG 3.1.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

html-xml-lang-mismatch

#

HTML elements with lang and xml:lang must have the same base language

The lang and xml:lang attributes disagree on the same element, which is common in XHTML-era markup.

How to fix

  • Set both attributes to the same language, or remove xml:lang (rarely needed in HTML5).
WCAG 3.1.1A Full reference (dequeuniversity.com) ↗ ← Back to scanner

form-field-multiple-labels

#

Form field must not have multiple label elements

A field has more than one <label> associated with it, which can produce confusing or duplicated announcements.

How to fix

  • Keep one label per field; merge additional text into aria-describedby if required.
WCAG 3.3.2A Full reference (dequeuniversity.com) ↗ ← Back to scanner

4. Robust

Content must work with assistive tech; valid markup and unique IDs.

button-name

#

Buttons must have discernible text

A <button> (or role="button") element has no accessible name; screen readers announce only "button".

How to fix

  • Add text content, aria-label, or aria-labelledby.
  • Icon-only buttons require an aria-label describing the action.

input-button-name

#

Input buttons must have discernible text

An <input type="button|submit|reset"> has no value or text, so its purpose is unknown.

How to fix

  • Set the value attribute (for example, value="Search").
  • Or use a <button> element containing text.

summary-name

#

Summary elements must have discernible text

A <summary> element (the clickable part of <details>) has no text, so users cannot determine what it expands.

How to fix

  • Place descriptive text inside <summary>.
  • If it is icon-only, add an aria-label.

aria-command-name

#

ARIA commands must have an accessible name

An element with an ARIA role such as link, button, or menuitem has no accessible name.

How to fix

  • Add aria-label, aria-labelledby, or text content.
  • Prefer native elements (<a>, <button>) over ARIA roles where possible.

label

#

Form elements must have labels

An input, select, or textarea has no associated <label>, aria-label, or aria-labelledby; screen readers announce "edit text" without indicating the field’s purpose.

How to fix

  • Wrap the input in a <label>, or use for="id" matching the input’s id.
  • Or add aria-label="..." or aria-labelledby.

select-name

#

Select element must have an accessible name

A <select> dropdown has no label, so users cannot determine what they are choosing.

How to fix

  • Associate a <label>, or add aria-label / aria-labelledby.

aria-valid-attr

#

ARIA attributes must conform to valid names

An aria-* attribute is misspelled or does not exist (for example, aria-lable), so browsers ignore it.

How to fix

  • Correct the typo; valid names are defined by the ARIA specification (aria-label, aria-hidden, aria-describedby, and so on).

ARIA roles used must conform to valid values

A role="..." value is misspelled or is not a real ARIA role, so assistive technology cannot interpret the element.

ARIA hidden element must not be focusable or contain focusable elements

Content hidden with aria-hidden still contains keyboard-focusable elements, so keyboard users tab into invisible content.

IDs used in ARIA and labels must be unique

Frames must have a unique title attribute

axe flags these as good practice, not WCAG failures; fixing them still helps users.

image-redundant-alt

#

Alternative text of images should not be repeated as text

An image’s alt text is also rendered as visible text adjacent to the image, so screen readers announce it twice.

How to fix

  • Keep the alt text concise and remove the duplicated visible text, or do the reverse.
  • If the visible text conveys additional information, shorten the alt text instead.

tabindex

#

Elements should not have tabindex greater than zero

tabindex="1+" overrides the natural tab order, forcing keyboard users into an unexpected sequence.

How to fix

  • Use tabindex="0" to add an element to the tab order, or tabindex="-1" for programmatic focus only.
  • Correct the DOM order instead of overriding it.
